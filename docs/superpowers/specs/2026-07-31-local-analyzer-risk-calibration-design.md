# 本地分析器风险置信度校准设计

## 目标

升级本地 `BlocklistAdvisor`，解决攻击量受单一极端 IP 扭曲、失败/拒绝/404 未参与风险判断、致命等级漏算，以及评分证据不足的问题。采用用户确认的偏激进策略：高频失败扫描可以进入“建议封禁”，但“立即封禁”仍需高危载荷、多阶段攻击链、明显放行响应或强历史证据。

## 范围

修改范围：

- `analyzer/SXF_extract_attacker/modules/blocklist_advisor.py`
- `analyzer/SXF_extract_attacker/tests/test_blocklist_history_loop.py`
- 必要时扩展流水线标准化字段与报告展示，但保持现有字段兼容

不修改：

- 数据库 schema
- SIP 查询与导出逻辑
- 防火墙执行逻辑
- `--apply` 默认行为
- 外部 AI/模型依赖

## 当前问题

真实导出基线为 22,277 条日志、2,877 个源 IP。现有引擎存在以下偏差：

1. 攻击量按本批次最大攻击次数线性归一化。单个 4,449 次攻击源会压低其余 IP 的量分，跨批次分数不可比较。
2. “动作”“攻击结果”“HTTP 状态码”“目标多样性”未进入评分。
3. 4,449 次攻击源中 4,128 条失败、4,346 条 404，仍可仅凭攻击量、严重度和类型得到 75.5 分并判为立即封禁。
4. “致命”未被当前严重度逻辑识别为高危。
5. 输出没有允许率、拒绝率、失败率、404 率、目标数和校准理由，难以审计。

## 评分架构

### 1. 稳定攻击量分

将攻击量从“相对本批次最大值”改为 `log1p` 分段计分，不再依赖同批次其他 IP：

- 3-9 次：低量基础分
- 10-49 次：中低量
- 50-199 次：中量
- 200-999 次：高量
- 1000 次及以上：满量分

实现使用连续 `log1p(count) / log1p(1000)`，封顶 20 分，避免硬阈值跳变。

### 2. 行为置信度

新增 `behavior_confidence` 维度，最多 15 分，输出原始比率与理由：

正向信号：

- 允许动作比例较高
- 2xx/3xx 响应比例较高
- 多目标攻击
- 同一 IP 命中多个高危攻击阶段

负向信号：

- 拒绝比例较高
- 明确失败比例较高
- 404 比例较高

负向信号降低“可能已利用”的置信度，但不抵消恶意意图；行为分最低为 0，不对总分做负扣分。

### 3. 高危意图底座

识别以下高危类型或证据：

- 命令执行、代码执行、RCE
- WebShell 上传/后门
- 反序列化
- 明确命令 Payload，例如 `/bin/sh`、`cmd.exe`

高危意图用于推荐门控，不依赖攻击结果是否成功。严重度识别补充“致命”“critical”。

### 4. 其他维度

保留威胁多样性、严重度、持续性、攻击链、Payload 和历史评分，但调整总权重以容纳行为置信度：

- 攻击量：20
- 威胁多样性：10
- 严重度：20
- 持续性：10
- 攻击链：10
- Payload：15
- 行为置信度：15
- 历史分仍作为额外加分，封顶 15；最终分仍封顶 100

## 推荐策略

### 立即封禁

最终分达到 70，且至少满足一项：

- 明确高危意图，并存在允许/有效响应信号
- 覆盖至少 3 个攻击阶段
- 明确高危 Payload 且历史重复推荐

单纯高频失败扫描不得进入立即封禁。

### 建议封禁

满足最终分门槛和当前恶意证据，并符合任一条件：

- 高频失败扫描：至少 200 次，且扫描/探测/漏洞利用特征明确
- 高危意图，即使攻击结果为失败或被拒绝
- 多目标持续攻击
- 当前攻击证据加历史重复记录

### 持续监控与观察

不满足封禁门控时保留现有分级。历史分不能单独把低风险当前行为推入封禁建议。

## 输出契约

在现有输出字段基础上新增：

- `behavior_confidence_score`
- `allowed_rate`
- `blocked_rate`
- `failed_rate`
- `not_found_rate`
- `target_count`
- `high_risk_intent`
- `calibration_reasons`

旧字段 `base_score`、`history_score`、`final_score`、`recommendation`、`recommendation_reasons` 保持不变。CSV、标准化 CSV、Markdown/JSON 报告按可用字段增量展示。

## 错误与降级

- 缺失动作、结果、状态码或目标字段时，该子信号记为不可用，不报错。
- 行为置信度不能因为字段缺失而获得默认高分。
- 无 HTTP 场景不以缺少状态码降分。
- 历史查询失败继续回退到当前基础分，并记录查询失败原因。

## 测试策略

按 TDD 增加以下测试：

1. 攻击量分不受同批次极端 IP 影响。
2. 致命等级计入高危比例。
3. 高频失败/拒绝/404 扫描可以建议封禁，但不能立即封禁。
4. 高危 RCE/WebShell/反序列化即使失败仍保留高危意图。
5. 明确高危意图加允许/2xx 信号可进入立即封禁。
6. 缺失行为字段时兼容现有输入。
7. CSV 包含新增校准字段且保留旧字段。
8. 历史分不能单独提升低风险当前行为。

## 验证

1. 运行分析器定向测试。
2. 运行项目全套 pytest、`py_compile` 和 `git diff --check`。
3. 使用 `runs/20260731_163422` 的 22,277 条合并日志做只读离线对比：不持久化历史、不调用防火墙、不执行封禁。
4. 输出升级前后候选数量、分级变化和 Top 候选的校准理由。
5. 人工检查原 4,449 次、4,346 条 404 的源 IP：允许进入建议封禁，但不得仅凭失败扫描进入立即封禁。

## 安全边界

本次升级只改变分析与建议，不自动开启 `--apply`。真实封禁仍由现有白名单、最大目标数、执行开关和审计记录控制。

## 实施状态（2026-07-31）

已完成实现和验证：

- 攻击量改为固定 `log1p` 刻度，并补齐“致命”严重度识别。
- 接入动作、攻击结果、HTTP 状态码和目标数行为置信度。
- 高频失败扫描可以进入“建议封禁”；压倒性失败或 404 不能仅凭多阶段标签进入“立即封禁”。
- 高危英文短词使用边界匹配，避免 `rce` 误命中 `force`。
- HTTP 响应率以该 IP 全部事件为分母，并记录状态码覆盖率，避免稀疏 2xx 被放大。
- 否定动作/结果不会被解释为允许或成功，高危意图不再只检查前 500 条。
- 原始 CSV、标准化 CSV、日报 JSON/Markdown 已增量接入校准证据字段，旧字段保持兼容。
